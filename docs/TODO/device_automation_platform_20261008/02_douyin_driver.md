# 抖音 driver

## 旧状态

仓库里没有抖音的 UI driver。相关资产只有两份。

- `examples/douyin_download.ts` 只做分享链接的网络解析与下载，完全不碰 UI，其中的链接正则可以直接复用
- `examples/automatic_xiaohongshu_assistant.ts` 与 `examples/automatic_bilibili_assistant.ts` 是同构的参考，但都是单体脚本，靠 `findById` 定位语义化 id，这套写法在抖音不成立

## 意图

实现抖音采集，`requiredTier` 为 accessibility。依据见 [index.md](index.md) 的实测基线：Shizuku 档读不到搜索结果页。

实现要点，均已在真机验证：

- `search` 用 `Tools.System.intent` 发 `snssdk1128://search?keyword=<urlencoded>`，并显式指定包名 `com.ss.android.ugc.aweme`
- 搜索页加载后先点「视频」标签。默认的「综合」标签里混着直播与图文，直播间没有分享链接面板，滑动还会直接滑进直播间
- 「视频」标签是两列网格，卡片封面没有 content-desc，用卡片右下角的时长角标（`^\d{2}:\d{2}$`）定位并点开第一张卡片，进入视频详情页
- 之后只在详情页内工作：详情页本身是竖向视频流，取完一条后向上滑即可切到下一个视频，不必返回搜索结果页
- 每条流程：点详情页分享按钮 → 点面板里的 `分享链接` → 点面板项前先确认它在可视区内（面板高度会变，有联系人行时该项会被推到导航栏下面）→ 关掉面板 → 从评论输入框回读剪贴板 → 清空输入框 → 收起评论面板
- 读回剪贴板用「粘贴进输入框再读回」。粘贴目标必须是详情页的评论输入框；搜索结果页只有搜索框，用它回读会触发重新搜索
  - 这条当初是用 shell 的 `input keyevent 279`（粘贴）与 `input keycombination 113 29` + `input keyevent 67`（清空）实现的，因此把采集绑死在了 Shizuku 上。2026-10-15 已改成纯无障碍原语：长按评论框后点抖音自己的粘贴工具条，清空走 `set_input_text`。改动与真机回归记录见 [collector_accessibility_only_20261015](../collector_accessibility_only_20261015/index.md)
- 宿主的 `read_clipboard` 在目标应用位于前台时读到的是空字符串，这是 Android 10 起的焦点限制，实测探针在 Operit 前台时可读到 120 字符完整文本，同一份代码在抖音前台时读到 0 字符。因此采集流程不用它
- 切下一个视频前先把页面恢复到视频画面。取链时点过评论框，返回键有时只收起了键盘，页面仍停在评论区，此时互动条不在画面里，滑动会变成滚页面
- 切换是否成功按分享按钮 content-desc 里的计数变化判断，连续多次没变化即报错，不允许无限滑动

定位规则：

- 一律使用文案的前缀或部分匹配。resource-id 被混淆且随版本变化，不得作为主定位手段
- content-desc 内嵌动态计数与状态词，例如详情页的 `分享1461，按钮`，断言时不能使用整串。图文作品的分享按钮没有「，按钮」后缀，只按前缀匹配更稳
- class 名要用简名，例如 `EditText`。无障碍档给简名，shell 档给全名，简名加部分匹配两边都能命中
- 可见性必须并进匹配条件一起判断。分成「先取首个匹配、再判断可见性」两步会先选中边界被裁掉的同名节点，再把它否掉，最后误报成找不到
- 被滚出屏幕的节点会给出反向边界，例如 `[56,354][723,70]`；只比较上边坐标会把这种节点当成可见，算出的中心点可能落在顶部搜索栏上
- 判断页面用节点特征而不是 `activityName`，后者有时返回根视图类名
- 文案表按版本维护，当前版本是 37.8.0

失败处理：

- 任一关键节点找不到即抛错并落现场，不尝试其他点位
- 滑动与面板上带都有次数上限，并且要判定是否真的前进，不允许无限重试。2026-10-08 的实测中正是因为缺少这个判定而出现死循环
- 取链后立即清空评论输入框，既不把内容接在后面，也不留下评论草稿

## 期待结果

输入关键词与条数，产出形如 `{url, shareText, keyword, collectedAt}` 的记录集合，交由 [03 记录落地与 outbox 上报](03_record_store_and_outbox.md) 处理。每条采集成功即写盘，中途失败不丢已采结果。

## 验证

真机上按顺序逐步验证，均已完成。

1. deep link 触发后，`getPageInfo` 返回的 Activity 是 `search.activity.SearchResultActivity`
2. 单条采集返回匹配 `v.douyin.com` 的 URL
3. 详情页内滑动切换视频后，分享按钮的 content-desc 计数确实变化，说明真的换了一条
4. 多条采集不重复采集同一个视频

2026-10-08 稳定性实测结果：

| 条数 | 结果 | 备注 |
| --- | --- | --- |
| 10 | 10/10 | 切到「视频」标签并改用时长效标定位之后 |
| 20 | 20/20 | 19 次视频切换，全程无错误，20 条链接互不重复，耗时约 13 分钟 |

单条耗时约 35 到 40 秒，瓶颈在分享面板的动画等待与两条固定 sleep。
