# 记录的相关性与推广标记

## 现状

06 步把遍历钉在搜索结果页里之后，推荐流不再被当成搜索结果。但搜索结果**内部**本来就会混进推广内容，用户也实际看到了瑞幸的广告视频。于是"要不要根据内容过滤"成了新问题。

## 为什么不做内容过滤

先量了数据，再决定不做：

| 判据 | 在 50 条正常结果上的命中 |
| --- | --- |
| 标题含"朗诵" | 25 |
| 含"朗诵"或"诵读" | 27 |

剩下的是《致橡树》《为你读诗》《余秋雨的秋》这类内容——主题完全相符，只是标题里没有那两个字。**按关键词过滤会丢掉约一半好数据**，比混进几条广告更糟。

还试过一种看起来更聪明的判据：详情页有没有「相关搜索」。实测广告页也有，而且是广告自己的相关词（`相关搜索 · 瑞幸高蛋白莓果酸奶饮团购`），与正常页无法区分。

结论：内容判据不可靠，客户端不做丢弃。

## 意图

把判断权交给服务端，客户端只提供两个客观标记：

- `keyword_in_title`：标题或话题里是否出现本次搜索关键词
- `promo_hint`：详情页上是否出现推广类标记词

标记只写进记录，不影响采集与否。

`promo_hint` 的词表是：广告、赞助、推广、团购、优惠券、新人券、立即购买、了解更多、查看详情、抢购、下单、门店、直播中。

## 已知局限

- 两个标记都是**线索不是判据**。`keyword_in_title` 在主题相符的内容上只有约一半命中；`promo_hint` 会被评论区里出现的同名词命中
- 所以服务端应先统计分布、确认准确率，再决定是否据此丢弃
- 广告页上是否还有更可靠的结构标记（广告角标、行动按钮），本步骤没有探明

## 作用域

- `my-packages/douyin-collector/src/packages/douyin_collector.ts`：记录类型加两个字段，取链时读详情页算 `promo_hint`，落记录时算 `keyword_in_title`

## 验证清单

1. 新采集的记录里两个字段都有值，且类型正确
2. 对已知的广告样本，`promo_hint` 应为真；对典型的正常样本，`keyword_in_title` 的命中分布与实测比例接近
3. 加上字段后上报链路不受影响

## 验证结果

| 验证项 | 实测 |
| --- | --- |
| 字段写入 | 新采集的记录都带 `keyword_in_title` 与 `promo_hint`，类型为布尔 |
| 关键词标记的判定 | 原创朗诵作品《主角》为真；《致橡树》《粗缯大布裹生涯 # 读书》《穿越千年与李清照相逢》为假。与"主题相符但不含关键词"的实测比例一致 |
| 推广标记的判定 | 本批 7 条全为假，页面确实没有推广标记。真值为真的情形只在广告页出现 |
| 上报链路 | 加字段后上报未受影响（服务端忽略未知字段） |
