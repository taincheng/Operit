# 01 快手 driver 与定位规则

## 旧实现情况

快手的采集代码此前不存在。可参照的两份实现：

- `my-packages/douyin-collector/src/packages/douyin_collector.ts`：详情页内滑动遍历
- `my-packages/xhs-collector/src/packages/xhs_collector.ts`：逐卡回列表遍历，含 `seenCardKeys`、`CardUnusableError`、`noProgressScrolls`

快手的形态更接近小红书那一份：详情页是连续信息流，不能用来遍历。

## 意图

一份 driver，按关键词走「搜索结果 → 逐卡进详情取分享链接 → 回列表」的闭环，把结果交给采集循环。定位规则全部走无障碍 provider 档，不依赖 uiautomator。

## 定位规则

| 目标 | 规则 | 实测依据 |
| --- | --- | --- |
| 快手在前台 | `Tools.UI.getPageInfo().packageName === "com.smile.gifmaker"`，不在就 `startApp` 后轮询 | 与抖音同构 |
| 搜索结果页就绪 | `resource-id` 以 `search_result_text` 结尾的 TextView，`text` 等于本次关键词 | 搜索框内容就是关键词 |
| 视频标签 | `resource-id` 以 `:id/tabs` 结尾的容器，子树里 `className==="View"` 且 `clickable` 的节点按左边界排序，下标 2 | 7 个自绘标签依次是 综合/直播/视频/用户/智能/商品/图集；视频中心 `(440,289)` |
| 视频标签已生效 | 树里没有**边界有效**的 `resource-id` 以 `:id/appbar` 结尾的容器，且出现 ≥1 张作品卡片 | 切到「视频」后 provider 树仍留着「综合」的 `appbar`，但 bounds 退化成 `[0,352][-1080,491]`；不带边界过滤会永远判假 |

| 卡片是否已渲染 | 子树里有形如 `01:02` 的时长文本 | 未渲染的卡片子树里只有 desc，读不到时长/日期/点赞（卡片 [2] [3] 实测） |
| 详情页 | `resource-id` 以 `forward_button` 结尾（正常页）或 `ad_card_container_root`（广告页），都要求边界有效 | 两类页面结构不同，都没有就是还没加载完 |
| 广告页 | `resource-id` 以 `ad_card_container_root` 结尾的节点存在 | 广告页右侧互动条整条不在；包内实测命中两次并整条跳过 |
| 分享入口 | `resource-id` 以 `forward_button` 结尾且边界有效 | desc 形如 `分享926`，计数会变 |
| 面板项 | `text` 恰为 `复制链接`，点它的可点击祖先；**按祖先判可见性**，祖先不在可视区就把面板往上带 | 祖先是 `share_to_layout`；面板项顺序会变（实测同片内分别在第 1/2 列），按坐标点会点到「作品举报」；实测两种屏幕外形态：整行在外（`[455,2924][624,3227]`）、文案可见而祖先在外（`[455,4336][624,4617]`、`[455,2681][624,2984]`） |
| 评论入口 | `content-desc` 前缀 `评论框` 且可见 | 实测全文 `评论框发条有爱评论~` |
| 评论编辑器 | `resource-id` 以 `editor` 结尾的 EditText | 评论区在原 Activity 内联展开 |
| 分享短链 | `/https?:\/\/v\.kuaishou\.com\/[^\s]+/` | 短链在分享文本最前面 |
| 作者 | `resource-id` 以 `user_name_text_view` 结尾的 TextView，去掉前导 `@` | 分享文本里没有作者 |
| 标题 | 分享文本里短链之后、`该作品在快手` 之前的正文 | 详情页 `element_caption_label` 被截断，尾部带 `… 展开` |

## 遍历与卡片身份

**逐卡回列表**，不进详情页内滑动。两个理由：

1. 快手详情页是连续信息流，滑到搜索结果用尽后会接到推荐流；而快手详情页上**没有**可靠的「我还在结果集里」标记。实测过 `相关搜索`（`resource-id` 以 `general_entry_pre_title` 结尾）当成判据，它在 12 次连续滑动里时有时无，同一批作品里隔条出现，不能当判据
2. 实测返回列表后卡片坐标**完全不变**，包括走完整取链流程之后。所以在读页时记下每张卡的中心点，处理完一张回列表再按记下的坐标点下一张即可

**卡片身份键**取「左边界 + desc + 时长 + 日期 + 点赞数或广告 + 卡片标题」，用于本片内避免重复处理同一张卡。

只有**已渲染**（子树里有 `01:02` 形式的时长文本）的卡片才进候选。未渲染的卡片子树里只有 desc，身份键退化成「左边界 + 作者」，同一作者在同一列有两张卡时会撞键、导致其中一张被静默跳过。**不要**为了让未渲染的卡也能采而去掉这条限制：卡片会在往下滚之后渲染出来，那时再采不会漏，而放宽限制会引入真的漏采。

已知代价：卡片被往下滚之后如果补齐了时长/日期/点赞，身份键会与之前那条不同，于是被当作新卡再走一次取链流程，最后由短链去重挡下。这是可控的浪费，不是漏采。

## 卡片不可用与广告页

- **广告页**（`ad_card_container_root`）：整条跳过，计入 `skippedAds`，不占本片条数目标，不做失败处理
- **形态采不动**：等某个定位器超时归为 `CardUnusableError`，跳过该卡继续下一张，计入 `skippedUnusable`；连着 5 张都这样说明不是单张卡的问题，抛错中断本片
- 两者都要先**退回搜索结果页**再继续。退回是「退一层、看一次」，最多 3 层；退不回去抛错中断本片

## 滚动

- 一次滚 600px（`CARD_SCROLL_STEP_PX`），与小红书同量级：卡片高约 1000–1200px，小步滚保证不漏卡，重叠部分由身份键跳过
- 滚动必须带前进判定：滚动前后「可见卡片的身份键序列」一致就记一次 `noProgressScrolls`，连续 3 次认为结果集到底，`stopReason=search_exhausted`

## 剪贴板回读

唯一可行通道是「粘进输入框再读回」，理由与抖音、小红书一致：Android 10 起只有持有焦点的应用能读剪贴板，采集时前台是快手。快手这一段的细节：

1. 点评论入口，评论区在原 Activity 内联展开
2. 点 `editor`，`input keyevent 279` 粘贴
3. 等 `editor` 的 `text` 命中分享短链正则
4. 无论成败都清空：`input keycombination 113 29` + `input keyevent 67`，再按一次返回键关闭编辑器

## 单条工具与批量采集共用

`ks_collect_share_link`（当前详情页取一条）与 `ks_collect_share_links`（批量）共用同一个 `extractShareOnDetailPage`，避免两处逻辑各自漂移。

## 预期结果

- `ks_collect_share_links({keyword: "家装", count: 3, chunk_minutes: 5})` 能取到 3 条不同的 `v.kuaishou.com` 短链，写进 `records.jsonl` 并各建一条 pending 的 outbox 记录
- 广告作品被跳过且不占条数目标
- 结束原因写进 `progress.json`
- 单条工具在作品详情页能取出短链与分享文本，在广告页如实报错

### 排障中修掉的三个缺陷

1. **「视频标签已生效」永远判假**：`appbar` 判据没做边界过滤，而 provider 树保留的「综合」残留节点 bounds 是退化的。修法是把 `parseBounds` 并进判据，并把同一层过滤补到按 id 取节点的全部定位器（分享入口、广告标志、作者、评论输入框）
2. **分享面板把「复制链接」推到屏幕外时直接判成采不动**：改成抖音那套「按文案定位 + 不在可视区就把面板往上带 + 带上限」，带上限失败才抛 `CardUnusableError`
3. **可见性判据查错了节点**：查的是「复制链接」这个文案节点，点的却是它的可点击祖先 `share_to_layout`，两者 `bounds` 不保证一致。实测文案落在可见区内、祖先在 `[455,4336][624,4617]`，于是屏幕外的祖先被白点一次、评论入口超时、这张卡丢掉。修法是先解析可点击祖先，再按祖先判可见性。修复后的轮次里这条路径实测生效（上带一次后点中，采不动的卡片 0 条）
